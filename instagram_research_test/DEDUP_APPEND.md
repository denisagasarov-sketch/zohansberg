# Дедупликация режима «Добавить новые посты» (append) — статус

Цель: при нажатии **➕ Добавить новые посты** пайплайн собирает и анализирует
**только те посты, которых ещё нет** в листе «Посты», и дописывает их в таблицу,
не трогая старые строки.

## Что уже сделано (безопасные, изолированные части, no-op по умолчанию)

1. **Apps Script — новый read-only режим `get_sheet_data`**
   `apps_script/stage5d3_write_google_sheets_webapp.gs`
   Запрос: `{mode: "get_sheet_data", sheet_name: "Посты", column: "Ссылка"}`.
   Возвращает `data` — массив непустых значений колонки начиная с row 3.
   `column` ищется по подстроке заголовка (`"Ссылка"` → `"Ссылка на пост"`),
   либо как буква/индекс колонки. Таблицу не изменяет.
   ⚠️ Чтобы режим заработал, Apps Script нужно **передеплоить** (скопировать
   файл в редактор Apps Script и обновить веб-приложение).

2. **`collect_posts.py` — параметр `exclude_codes`**
   Фильтрует посты по `shortCode` до сохранения raw/index. По умолчанию `None`
   → поведение не меняется.

3. **`run.py` — чтение `PIPELINE_EXCLUDE_SHORTCODES`**
   Парсит CSV-список shortCode из env и передаёт в `collect_posts`. По умолчанию
   пусто → no-op. Полностью покрыто `run.py --dry-run`.

4. **Apps Script — фикс сопоставления по колонке «Конкурент»**
   `_writeSheet` и `_handleDeleteAccount` раньше жёстко сканировали колонку A в
   поиске `account_label`, но в текущем layout колонка A = «Дата записи», а
   username лежит в колонке B «Конкурент». Совпадений не было никогда → replace
   не чистил старые строки (**дубли при каждом прогоне**), delete **не удалял**
   строки аккаунта. Добавлен хелпер `_findColumnByHeader`; оба места теперь ищут
   колонку «Конкурент» по заголовку строки 1 (fallback на A, если заголовка нет).
   ⚠️ Требует редеплоя Apps Script.

Извлечение shortCode из URL таблицы: `https://www.instagram.com/p/<shortCode>/`
→ предпоследний сегмент пути.

## Что осталось (отложено — рискованно и не тестируется отсюда)

### A. Семантика append в Apps Script (write_mode игнорируется)
После фикса колонки (п.4) `_writeSheet` корректно находит строки аккаунта по
колонке «Конкурент», **очищает их и пишет заново** — это правильный replace.
Но `write_mode` всё ещё **игнорируется**: отдельного режима «дописать, не очищая»
нет. Поэтому текущий «append» в боте по факту = replace (после редеплоя — уже
без дублей).

Для настоящего «добавить только новые посты» нужно:
- в `_writeSheet` различать `write_mode`: при `append` **не** очищать строки
  аккаунта, а писать после последней строки листа (`lastRow + 1`);
- иначе, если включить Python-дедуп при текущей записи (replace), `_writeSheet`
  очистит все строки аккаунта и запишет только новые → **старые посты потеряются**.

Сейчас `append` ещё и в `REJECTED_MODES` (через `write_mode` не отклоняется, но
семантики нет).

### B. Per-sheet семантика
Append имеет смысл только для листа «Посты» (и, возможно, «Reels»). Профиль/Bio —
одна строка на аккаунт; их дописывание создаст дубли. Поэтому действие
«Добавить новые посты» в боте должно либо запускать только стейджи постов
(13→14→15→15b→16), либо append применяться только к листу «Посты».
Сейчас action `append` запускает **все** стейджи.

### C. Проводка в боте (зависит от A и B)
В `accrun:append` нужно перед запуском:
1. вызвать Apps Script `get_sheet_data` (sheet «Посты», column «Ссылка»),
2. извлечь shortCode из URL,
3. выставить `env["PIPELINE_EXCLUDE_SHORTCODES"]` в `_run_pipeline_task`.

## Почему отложено
- Правки Apps Script выполняются на стороне Google и **не тестируются** из этого
  окружения (нужен ручной редеплой веб-приложения).
- Ошибка в логике append/clear = **безвозвратная потеря строк** в таблице.
- Части A–C связаны: включать дедуп в боте (C) безопасно **только после** того,
  как в Apps Script появится настоящий append (A: `write_mode=append` → запись
  без очистки строк аккаунта) и он будет ограничен листом постов (B). Частичное
  включение опаснее, чем его отсутствие.

Поэтому реализованы только безопасные примитивы (чтение + фильтр как no-op),
а деструктивная проводка оставлена выключенной до правки и редеплоя Apps Script.
