# Focus Board — многоагентный оркестратор задач

Автономный цикл, который берёт задачи из [плана работ](adhd-work-plan.md), реализует их, сам проверяет и сам одобряет (ревью агента агентом), затем двигается к следующей. Ниже — устройство, роли и точные промпты, чтобы цикл можно было запускать повторно.

## Роли

- **Оркестратор** (ведущий агент). Выбирает следующую незаблокированную задачу из плана, ведёт статус в task-виджете, снапшотит целевые файлы, вызывает Реализатора и Ревьюера, применяет гейт-политику, двигается дальше. Сам код не пишет.
- **Реализатор** (subagent, свежий контекст). Получает одну задачу с критериями приёмки и файлами. Делает минимальную правку строго под задачу. Возвращает: список изменённых файлов + краткое описание диффа.
- **Ревьюер** (subagent, свежий контекст, **не видел** реализацию). Получает задачу, критерии приёмки и дифф. Независимо проверяет: (1) дифф решает задачу и ничего лишнего; (2) `npx tsc --noEmit` в `v2/frontend` проходит (exit 0); (3) нет очевидных регрессий/сломанной логики. Возвращает вердикт `APPROVE` или `REQUEST_CHANGES` + причины.

## Цикл на одну задачу

```
для каждой задачи T из очереди:
  1. TaskUpdate(T) → in_progress
  2. snapshot: cp целевые файлы → *.orchestrator.bak
  3. attempt = 1
  4. Implementer(T, feedback=None) → делает правку
  5. diff = diff(*.bak, текущие файлы)
  6. Reviewer(T, diff) → verdict
  7. если verdict == APPROVE:
        rm *.bak ; TaskUpdate(T) → completed ; следующая задача
     иначе если attempt < MAX_RETRIES (=2):
        attempt++ ; Implementer(T, feedback=причины ревьюера) → шаг 5
     иначе:
        оставить как есть, TaskUpdate(T) метка "needs human" ; эскалация оркестратору
```

## Гейт-политика

- **Одобрение — только от Ревьюера**, который не видел ход реализации (независимость).
- **Обязательный машинный сигнал:** `npx tsc --noEmit` (exit 0) в `v2/frontend`. Красный типчек = автоматический `REQUEST_CHANGES`, что бы ни говорил визуальный разбор.
- **Скоуп-контроль:** дифф должен трогать только файлы задачи. Лишние правки = `REQUEST_CHANGES`.
- **Ретраи:** максимум 2 круга. После — задача помечается «needs human», цикл идёт дальше, не застревая.
- **Изоляция диффа:** т.к. `v2/` не в git-индексе, дифф считается против `*.orchestrator.bak`, а не `git diff`.

## Промпт Реализатора (шаблон)

> Ты — Реализатор. Задача **{ID}**: {описание}. Файлы: {пути}. Критерии приёмки: {критерии}. Внеси **минимальную** правку строго под задачу — ничего сверх. Не рефактори лишнего. По завершении верни: изменённые файлы и 3–5 строк, что именно поменял и почему это удовлетворяет критериям. {feedback ? «Ревьюер вернул на доработку: {feedback}. Исправь.» : ''}

## Промпт Ревьюера (шаблон)

> Ты — независимый Ревьюер, реализацию не видел. Задача **{ID}**: {описание}. Критерии приёмки: {критерии}. Ниже дифф:\n{diff}\n\nПроверь: (1) дифф выполняет критерии и не содержит лишнего; (2) запусти `cd v2/frontend && npx tsc --noEmit` и убедись, что exit 0; (3) нет очевидных регрессий. Верни строго: `VERDICT: APPROVE` или `VERDICT: REQUEST_CHANGES` + маркированный список причин. Если типчек красный — обязательно REQUEST_CHANGES.

## Как масштабировать на весь план

Очередь = задачи из `adhd-work-plan.md` в порядке спринтов (0→4). Оркестратор берёт по одной незаблокированной; задачи, трогающие один файл (напр. F4 и B1 — оба `PhaseDay.tsx`), идут последовательно во избежание конфликтов; независимые (напр. C3 в `MorningWizard.tsx`) можно параллелить. Для крупных задач (A1, A2, C1) ставить `MAX_RETRIES=3` и добавлять в критерии приёмки скриншот-проверку.
